# Go Backend Route and Service Inventory

## Scope and evidence

Inventory derived from `go-game-service-platform/main.go` route registration and `internal/controller/http/*.go` handlers. This records current implemented Go behavior. Linked IFA/API contracts are draft proposals and do not establish that Go currently implements their request, response, or business rules. Source paths below are relative to `go-game-service-platform/`. `writeJSON` envelopes generally contain `code`, `message`, and optional `data`; exact status/code/message are summarized where stable. Handler-specific failures use controller error translators. Refer to source for exhaustive wording.

## Cross-cutting behavior

- Route registration and dependency wiring: `main.go`; all endpoints served by `net/http` ServeMux.
- Admin handlers verify admin access token from Bearer header or admin cookie, then permission-check. Permission strings vary by feature (`orders-manage`, `finance-read`, `settings-manage`, `dashboard-read`, etc.). See each `*_http.go`.
- Auth endpoints issue HttpOnly access/refresh cookies; customers use `__Host-jokihub-session` and refresh cookie; admins use `jokihub-admin` and refresh cookie. Access lifetime 900 seconds; refresh lifetime 7 days. Cookies use SameSite by account type; security flags depend on account type / NODE_ENV.
- CORS and request logging wrap mux in `main.go`; implementation: `cors.go`, `request_logging.go`.
- JSON body decoder limits body to 1 MiB, disallows unknown fields, and rejects multiple JSON values (`auth_http.go` helper shared within package).
- Rate limit repository configured at startup; auth and proof operations invoke rate-limiter.
- Persistence: MongoDB repositories. Email: SMTP sender. Proof storage: blob storage. Env/config details in `config/database.go` and infrastructure packages.
