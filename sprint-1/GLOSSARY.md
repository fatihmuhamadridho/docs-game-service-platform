# Sprint 1 Glossary

Istilah berikut digunakan dalam BRD, acceptance criteria, HLD, ERD, dan solutioning Sprint 1. Istilah khusus fitur dijelaskan di dokumen fiturnya.

| Istilah                              | Definisi                                                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Acceptance Criteria (AC)             | Kondisi yang dapat diverifikasi untuk menentukan apakah kebutuhan atau cerita pengguna terpenuhi.                        |
| Admin Account                        | Identitas administrator untuk mengakses dashboard dengan permission yang ditetapkan.                                     |
| API                                  | Antarmuka yang digunakan aplikasi untuk bertukar request dan response.                                                   |
| API Contract                         | Spesifikasi endpoint, input, output, aturan, dan error API.                                                              |
| Authentication                       | Proses memverifikasi identitas administrator atau sistem.                                                                |
| Authorization                        | Pemeriksaan apakah identitas yang sudah terverifikasi boleh melakukan tindakan atau mengakses data tertentu.             |
| BRD (Business Requirements Document) | Dokumen yang menjelaskan konteks, tujuan, cakupan, kebutuhan bisnis, asumsi, dan pertanyaan terbuka.                     |
| Catalog                              | Kumpulan game yang dikelola untuk ditampilkan kepada pengunjung. Kategori dan layanan berada di scope sprint berikutnya. |
| Dependency                           | Keputusan, sistem, pihak, atau hasil kerja yang dibutuhkan sebelum pekerjaan lain dapat dilanjutkan.                     |
| ERD (Entity-Relationship Diagram)    | Diagram entitas data, atribut, dan hubungan antarentitas.                                                                |
| HLD (High-Level Design)              | Ringkasan flow sistem dan interaksi utama antarpengguna atau komponen.                                                   |
| IFA (Interface/Functional Analysis)  | Dokumen analisis solusi fitur atau API, termasuk alur, kontrak, validasi, response, dan error.                           |
| Permission                           | Hak untuk melakukan tindakan tertentu pada fitur atau data.                                                              |
| RBAC (Role-Based Access Control)     | Model kontrol akses yang mengelompokkan permission ke dalam role, lalu memberikan role kepada akun administrator.        |
| Super Admin                          | Satu-satunya role hasil seed awal Sprint 1; memiliki akses ke seluruh fungsi admin dan tidak dapat diubah atau dihapus.   |
| Session                              | Keadaan autentikasi yang memungkinkan pengguna melanjutkan akses setelah identitasnya diverifikasi.                      |
| TBD (To Be Determined)               | Hal yang belum diputuskan atau diketahui dan masih memerlukan tindak lanjut.                                             |
| Validation                           | Pemeriksaan bahwa input atau tindakan memenuhi format, aturan, dan batas yang ditentukan.                                |
| Visitor                              | Pengunjung yang menggunakan fitur publik.                                                                                |
