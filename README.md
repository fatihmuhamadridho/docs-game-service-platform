# Project Specification Documents

This repository contains reusable documents for describing project requirements, acceptance criteria, and API contracts. Use each template to create a project-specific document, and refer to its example for guidance.

## Documents

| Document                             | Template                                                             | Example                                                            | Purpose                                                                                             |
| ------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| Business Requirements Document (BRD) | [BRD.md](./BRD.md)                                                   | [BRD-EXAMPLE.md](./BRD-EXAMPLE.md)                                 | Describe business context, objectives, scope, requirements, assumptions, plans, and open questions. |
| Acceptance Criteria                  | [acceptance-criteria/TEMPLATE.md](./acceptance-criteria/TEMPLATE.md) | [acceptance-criteria/EXAMPLE.md](./acceptance-criteria/EXAMPLE.md) | Define user stories, verifiable outcomes, technical flow, and estimation details.                   |
| API Contract / Solutioning           | [solutioning/TEMPLATE.md](./solutioning/TEMPLATE.md)                 | [solutioning/EXAMPLE.md](./solutioning/EXAMPLE.md)                 | Specify API behavior, request and response contracts, validation, and status codes.                 |

## Current-State References

The [@current-state](./@current-state/README.md) folder contains references describing existing application behavior. Review relevant current-state documents when preparing new requirements or API contracts.

## Usage

- Copy the relevant template when creating a project document.
- Use the matching example to understand the expected level of detail and format.
- Replace placeholders and examples with confirmed project information.
- Keep unknown details explicit and resolve them with the responsible stakeholders.
