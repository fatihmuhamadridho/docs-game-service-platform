# Register Keputusan Terbuka Sprint 2

Dokumen ini merangkum keputusan yang dirujuk oleh BRD, HLD, ERD, dan IFA Sprint 2. Semua butir berstatus **terbuka** kecuali ada bukti persetujuan yang dicatat pada dokumen ini. Register ini bukan backlog story atau acceptance criteria.

| ID   | Keputusan yang diperlukan                                                                                                                                                                                   | Bukti penutupan                                                                                                                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | Product Owner menetapkan apakah halaman help, about, home, konten settings, dan state access-denied/not-found termasuk delivery Sprint 2 serta menyetujui kontennya.                                        | Scope dan konten halaman disetujui; setiap halaman yang tidak disetujui dinyatakan di luar delivery.                                                                                                                         |
| D-02 | Product/catalog owner menetapkan lifecycle dan eligibility kategori/layanan/game untuk penemuan publik dan pemilihan order.                                                                                 | Predicate eligibility per konteks admin, storefront, dan order disepakati, termasuk status aktif/nonaktif/terhapus dan relasi parent.                                                                                        |
| D-03 | Product/finance/API owner menyepakati fixed-price versus quote-required, pemilik currency, presisi dan representasi nominal, serta konsistensinya dengan order snapshot.                                    | Aturan harga dan currency disetujui lintas katalog publik dan checkout/order.                                                                                                                                                |
| D-04 | Data/API owner menetapkan model fisik MongoDB dari ERD logis: collection/field, ID, bounds, defaults, constraints aplikasi, indexes, dan lifecycle reference.                                               | Mapping logis-ke-fisik dan query/index plan ditinjau serta disetujui.                                                                                                                                                        |
| D-05 | Product/platform owner menetapkan kepemilikan settings, nilai/default yang dikelola, serta pemisahan settings admin dan proyeksi publik termasuk currency/timezone.                                         | Daftar field, owner, consumer, projection allowlist, dan aturan propagasi disetujui.                                                                                                                                         |
| D-06 | API/platform owner menetapkan apakah `version` mendukung optimistic concurrency, bentuk precondition, dan perilaku stale write.                                                                             | Kontrak request/response dan status conflict untuk update settings disepakati; bila tidak memakai compare-and-update, keputusan itu dinyatakan eksplisit.                                                                    |
| D-07 | Audit/security/product owner menentukan event boundary dan taxonomy untuk audit administratif, termasuk actor, action, target, outcome, waktu, redaksi, dan kebutuhan audit atas read/failure.              | Event catalog dan field allowlist disetujui serta memenuhi BR-022.                                                                                                                                                           |
| D-08 | Audit/platform/data owner menetapkan persistence/delivery, atomicity, retry/deduplication, append-only enforcement, failure policy, retention, actor erasure, akses, dan kebutuhan read/index.              | Jaminan audit write dan lifecycle disetujui; sequence serta kegagalan parsial konsisten di HLD, ERD, dan mutation IFA.                                                                                                       |
| D-09 | Product/security owner menetapkan tujuan, audience, exposure, field allowlist, cache/freshness, dan rollout untuk `GET /api/settings/v1/public`.                                                            | Route target, data yang boleh dipublikasikan, cache policy, dan kompatibilitas consumer disetujui.                                                                                                                           |
| D-10 | Public API owner menetapkan dukungan `page`/`limit`, unknown-query handling, default/batas pagination, dan kompatibilitas terhadap perilaku route kategori/layanan yang tercatat.                           | Query contract, validasi, pagination response, dan rollout disetujui untuk masing-masing public list API.                                                                                                                    |
| D-11 | API/security/platform owner menyepakati HTTP/service-code mapping, auth/session dan CSRF boundary, deployment exposure, serta rollout/compatibility pada route yang kontraknya berubah.                     | Matriks auth dan error mapping per route disetujui dan cocok dengan IFA serta middleware/deployment target.                                                                                                                  |
| D-12 | Product/platform owner menetapkan criticality, SLA dan NFT workload per endpoint berdasarkan forecast, kondisi ukur, dan hasil NFT.                                                                         | Target availability, concurrency/throughput, resource, latency, cakupan pengukuran, dan approval dicatat; baseline Sprint 1 di IFA tetap usulan sampai disetujui.                                                            |
| D-13 | Product Owner menetapkan disposition kandidat yang beririsan dengan Sprint 2/Sprint 3, termasuk password recovery, admin order/payment review, serta workflow/refund/payout lain.                           | Scope dan alokasi lintas sprint disetujui berdasarkan backlog kanonis; kandidat tidak otomatis dianggap masuk atau dikecualikan.                                                                                             |
| D-14 | Product/catalog/order owner menetapkan predicate count dan eligibility yang dipakai admin, storefront, dan order serta konsistensi lifecycle-nya.                                                           | Aturan count/publishability dan dampaknya pada response, query, relasi, dan order disetujui.                                                                                                                                 |
| D-15 | Product/PM menyediakan backlog atau indeks acceptance criteria Sprint 2 yang otoritatif dan memetakan dokumen ke story.                                                                                     | Backlog/index tersedia dengan story ID dan disposition yang dapat ditelusuri. Saat ini belum tersedia di repo; AC tidak dibuat dalam cakupan solutioning ini.                                                                |
| D-16 | Product/payment/platform owner menetapkan owner dan source of truth untuk instruksi pembayaran pelanggan Sprint 3, termasuk apakah berada di platform settings atau konfigurasi pembayaran terpisah.        | Field, owner, consumer, update/publish lifecycle, dan sumber instruksi pembayaran disetujui.                                                                                                                                 |
| D-17 | Product/PM menetapkan register BR-ID portofolio kanonis dan aturan pemakaian ID lintas sprint.                                                                                                              | Register kanonis tersedia dan pemetaan Sprint 2 disahkan; sampai itu, BR-ID pada BRD ini hanya berscope Sprint 2.                                                                                                            |
| D-18 | Product/access/API/security owner memilih reuse atau extension permission catalog untuk route kategori/layanan dan menetapkan stable key, route mapping, grant custom-role, UI, dan compatibility behavior. | Route-to-permission matrix serta delta/reuse keputusan disetujui dan custom-role grant behavior diverifikasi. Detail opsi ada di [permission catalog extension](./dashboard/accounts-roles/permission-catalog-extension.md). |
