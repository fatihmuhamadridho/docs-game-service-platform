# Public Catalog and Settings — Go Source Audit

Status: current implementation evidence recorded in this repository's catalog audit performed 2026-10-23. The audited routes use common response `{status:{code,message},data}`. All six routes are public reads, no authentication/authorization, no mutation, no idempotency key. Handlers do not reject unexpected request headers; query acceptance is listed per route. Exact storage failure diagnostics remain private and map to generic 500s.

## Headers and response details

No route requires Authorization, Cookie, custom request headers, or `Idempotency-Key`. Catalog success responses use JSON; no pagination `next` cursor. For headers such as `Accept`, source has no explicit validation; unsupported content negotiation behavior is therefore TBD at server/mux layer. `serviceSummary`, `artworkKey`, category description, `price`, and business hours can be null according to model values; source structs/maps determine serialization. Numeric price is converted from Decimal128 to float64; invalid decimal conversion becomes technical error.

## Target decisions kept separate

These source contracts do not imply desired CDN caching, response caching, throttling for catalog reads, public settings cache duration, strict behavior for the services alias, stable price decimal serialization, or expanding popular scan beyond 100. Approve these separately before changing implementation. See [catalog open contract decisions](QUESTION.md).
